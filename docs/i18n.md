# Languages

The app language is a setting (`System`, or one of the registered languages). `System` follows the browser languages and falls back to English. The registry is `packages/ui/src/i18n/locales.ts`; it is the single source of truth for the picker, the `language` setting values and `resolveLocale`.

## Adding a language

1. Add `packages/ui/src/i18n/xx.ts` (popup strings) and `packages/ui/src/manage/i18n/xx.ts` (manage strings), typed against the English keys.
2. Add one line to `LOCALES` in `locales.ts` and add the code to `LANGUAGE_VALUES` (a compile-time check fails if they drift apart). Write the native name with `\uXXXX` escapes for non-ASCII characters.
3. Register the dictionaries in `i18n.tsx` (`dictionaries`) and in `manage/i18n/index.ts`.
4. Add `apps/extension/public/_locales/xx/messages.json` for the browser-level texts.
5. The key-parity tests in `apps/extension/test/i18n-split.test.ts` must pass for the new language.

Both `tr` and `en` are bundled statically (English is the fallback for any missing key). Lazy per-language chunks are not implemented yet; add them when a third language would push the popup over its size budget.

## Limits

Browser-level texts (`extName`, the context menu entry and the keyboard shortcut descriptions) come from `_locales` and follow the browser language. They cannot be changed at runtime, so the language setting does not affect them.
